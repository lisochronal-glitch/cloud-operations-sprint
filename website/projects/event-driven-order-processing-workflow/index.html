AWS Event-Driven Workflow Project

Asynchronous SaaS Order Processing Workflow

A SaaS company needs to accept customer orders quickly while slower follow-up work, such as confirmation processing, audit logging, and internal workflow handling, happens reliably in the background.

This project will build a live AWS event-driven workflow using API Gateway, Lambda, SNS, SQS, DynamoDB, a dead-letter queue, and CloudWatch.

BUSINESS PROBLEM

Customer orders should be accepted quickly, even when background processing takes longer

In a SaaS application, the customer-facing request should not wait for every follow-up task to finish. Order confirmation, internal processing, audit logging, and failure handling can happen asynchronously after the order has been accepted.

The goal of this project is to demonstrate how AWS services can decouple the immediate customer request from slower backend processing work.

AWS SERVICES

Services planned for this project

  • API Gateway for accepting demo order requests from the project page
  • Lambda publisher function for validation and event publishing
  • SNS topic for event fanout
  • SQS processing queue for asynchronous backend work
  • SQS audit queue for retaining an independent copy of order events
  • Processor Lambda for background order handling
  • DynamoDB for order status tracking
  • Dead-letter queue for repeated processing failures
  • CloudWatch Logs and metrics for operational visibility
  • CloudFormation for repeatable deployment and cleanup
