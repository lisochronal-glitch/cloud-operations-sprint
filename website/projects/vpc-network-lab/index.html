AWS Networking Project

Secure VPC Foundation

This project designs a secure AWS network foundation for a small web application. The scenario is a company migrating from a local hosting provider to AWS. Customers must be able to access the public website from the internet, while the backend application and future database must remain isolated from direct public access.

The network is designed around a separated public web tier and private backend tier. The public subnet supports internet-facing resources, while the private subnet is reserved for backend components that should not be directly reachable from the internet. The design will be implemented with CloudFormation, verified through testing, documented with evidence, and removed after the lab is complete for cost control.

PROJECT SUMMARY

Secure public access with private backend isolation

Technologies used: Amazon VPC, public subnet, private subnet, route tables, Internet Gateway, Security Groups, EC2 test resources, and CloudFormation.

  • Designed a public/private AWS network foundation for a small web application.
  • Separated internet-facing web resources from private backend resources.
  • Used route tables and an Internet Gateway to control public internet access.
  • Used Security Groups to restrict traffic between network tiers.
  • Planned CloudFormation provisioning so the environment can be recreated and removed safely.
  • Will verify public web reachability and private backend isolation with screenshots and tests.

SOLUTION

Public web tier with isolated private backend tier

The solution uses an Amazon VPC with separate public and private subnets. The public subnet is connected to the internet through an Internet Gateway and is used for the web tier. The private subnet uses a separate route table and is reserved for backend components that should not be directly reachable from the internet.

This design follows a simple but realistic AWS networking pattern: expose only the resources that must receive customer traffic, keep backend resources private, and use Security Groups to control allowed communication between tiers.

SECURITY DECISIONS

Only the web tier is designed for public access

The main security decision is to separate the public and private parts of the application. The web tier can receive customer traffic, but backend resources are not placed in the public subnet and do not have direct public internet exposure.

  • The public subnet is used for internet-facing web resources.
  • The private subnet is reserved for backend application and future database resources.
  • Route table separation prevents the backend tier from having direct public internet access.
  • Security Groups restrict inbound traffic and communication between tiers.
  • No NAT Gateway is planned for the initial lab unless outbound private-subnet access becomes required.

COST CONTROL / CLEANUP

Temporary lab environment removed after verification

This project is designed as a temporary AWS lab. The environment will be deployed only long enough to test the network, capture evidence, and document the result.

After verification is complete, the CloudFormation stack will be deleted and cleanup will be confirmed. This demonstrates controlled use of AWS resources and avoids unnecessary ongoing charges.
