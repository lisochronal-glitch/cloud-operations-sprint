AWS Networking Project

Secure VPC Foundation

This project designs a secure AWS network foundation for a small web application. The scenario is a company migrating from a local hosting provider to AWS. Customers must be able to access the public website from the internet, while the backend application and future database must remain isolated from direct public access.

The design separates the application into a public web tier and a private backend tier. The public tier is built for internet-facing access, while backend resources are placed in a private subnet and protected through route table separation and Security Group rules. The infrastructure will be implemented with CloudFormation, verified through testing, and removed after the lab is complete for cost control.

SOLUTION

Public web tier with isolated private backend tier

The solution uses an Amazon VPC with separate public and private subnets. The public subnet supports internet-facing resources, while the private subnet is reserved for backend components that should not be directly reachable from the internet.

An Internet Gateway is attached to the VPC so the public subnet can route traffic to and from the internet. The private subnet uses a separate route table without a direct internet route. Security Groups are used to restrict allowed traffic and enforce a clear boundary between the public and private tiers.

AWS SERVICES / FEATURES USED

Core networking components

  • Amazon VPC for isolated network foundation
  • Public subnet for internet-facing web resources
  • Private subnet for backend application and future database resources
  • Route tables for separating public and private network paths
  • Internet Gateway for public web tier access
  • Security Groups for controlled inbound and internal traffic
  • EC2 test resources for connectivity verification
  • CloudFormation for repeatable infrastructure provisioning

SECURITY DECISIONS

Backend resources are not directly exposed to the internet

The main security goal is to expose only the resources that must be public. The web tier is placed in a public subnet so customers can reach the application, but backend resources are placed in a private subnet with no direct public route.

  • The public subnet is used only for internet-facing web access.
  • The private subnet is reserved for backend resources.
  • Route tables separate public internet access from private backend networking.
  • Security Groups restrict traffic between tiers.
  • The design can be extended later with additional private resources or a database tier.

Testing public access and private isolation

  • Confirm that the private backend tier is not directly reachable from the internet.

COST CONTROL / CLEANUP

Temporary lab environment removed after verification

This project is designed as a temporary lab. The environment will be deployed only long enough to test the network, capture evidence, and document the result.

After verification is complete, the CloudFormation stack will be deleted and cleanup will be confirmed. This demonstrates controlled use of AWS resources and avoids unnecessary ongoing charges.
